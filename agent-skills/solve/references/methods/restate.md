# Restate method

## Provenance: source and authored extensions

Shannon-derived core: reformulate a problem across words, representations, and
viewpoints to escape mental ruts. Authored extensions: the invariant ledger,
explicit relaxation labels, comparison, and mandatory map back.

## Shared entry contract

Use the fully loaded [shared workflow contract](../workflow-contract.md).
Consume its established or inherited problem contract without reconstructing
it or restarting a stakeholder interview. Preserve the original problem and
criterion IDs, fixed facts, constraints, non-goals, authorized work, unresolved
OPEN/ASSUMED items with their owners and questions, and remaining effort.
Conditional exploration follows that contract; it does not settle uncertainty.
This module is the same full method for the direct entry and router. It does
not invoke public leaf commands or grant additional action authority.

Apply the shared evidence, result-status, stopping, and composition rules.
A full execution consumes one attempt from the remaining shared budget,
including execution on a subproblem; loading this module does not reset it.

Use the original fixed facts, constraints, and success criteria as an invariant
ledger; non-goals remain constraints.

## Cheap candidate transformation

Sketch at least three genuinely different restatements or representations of
`P`, such as a concrete trace, a data or state view, and another actor's view.
Do not select one yet.

## Full method

1. Produce at least three genuinely different forms by changing vocabulary,
   representation, actor, quantity, time horizon, or boundary.
2. Check each form against the invariant ledger.
3. Label every intentional relaxation and state how it will be restored or
   resolved; never smuggle a changed constraint into the wording.
4. Compare what each form reveals, obscures, or makes answerable.
5. Reject mere paraphrases and formulations that embed a pet solution.
6. Select the strongest restatement and attack the problem through it.

## Result and map-back

Return the invariant ledger, restatements, comparison, selected form, and the
result it produced. Translate that result back to `P`, restore every labeled
relaxation, and verify fixed facts, constraints, and the original observable
success criteria. Reject a result that violates an invariant.

At this checkpoint, report definition status separately from resolution status
using the shared contract. Link evidence and gaps to the original criterion
IDs; distinguish supplied evidence, executed checks and observed results,
derived conclusions, and proposed checks. A proposed check is not passing
evidence. Preserve OPEN/ASSUMED owners and questions. An incomplete map-back
can return useful partial progress with its outstanding obligations and
remaining effort; success on a subproblem is not VERIFIED for the whole `P`.

## Failure modes

- Changing sentence order while preserving the same representation.
- Restating toward a favored implementation rather than exposing structure.
- Dropping fixed facts or success criteria during reformulation.
- Selecting a promising restatement without mapping its result back.
