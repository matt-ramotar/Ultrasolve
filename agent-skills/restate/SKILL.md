# Restate

## Direct-invocation boundaries

- If the problem is open-ended, underspecified, or undefined, use
  brainstorming when available; otherwise define or clarify it locally.
  When the collection is present, `../define/SKILL.md` performs that definition.
- If missing facts could change the route or answer, use research tools when
  available; otherwise ask the user for the missing facts.
- If a reproducible failure has an evidence trail, return to evidence-led
  diagnosis when available; otherwise perform it locally. This leaf provides
  only bounded transformation support inside diagnosis and does not replace it.

## Provenance: source and authored extensions

Shannon-derived core: reformulate a problem across words, representations, and
viewpoints to escape mental ruts. Authored extensions: the invariant ledger,
explicit relaxation labels, comparison, and mandatory map back.

## Entry contract

Before transforming anything:

1. State the original problem `P` in one paragraph.
2. State observable success criteria for the solution.
3. List fixed facts and constraints that may not be silently changed.
4. Identify and gather missing domain facts that could change the route or
   answer.

Use the fixed facts, constraints, and success criteria as an invariant ledger.

## Cheap candidate transformation

Sketch at least three genuinely different restatements or representations of
`P`, such as a concrete trace, a data or state view, and another actor's view.
Do not select one yet.

## Full method

1. Produce at least three genuinely different forms by changing vocabulary,
   representation, actor, quantity, time horizon, or boundary.
2. Check each form against the invariant ledger.
3. Label every intentional relaxation and state how it will be restored or
   resolved; never smuggle a changed constraint into the wording.
4. Compare what each form reveals, obscures, or makes answerable.
5. Reject mere paraphrases and formulations that embed a pet solution.
6. Select the strongest restatement and attack the problem through it.

## Result and map-back

Return the invariant ledger, restatements, comparison, selected form, and the
result it produced. Translate that result back to `P`, restore every labeled
relaxation, and verify fixed facts, constraints, and the original observable
success criteria. Reject a result that violates an invariant.

## Failure modes

- Changing sentence order while preserving the same representation.
- Restating toward a favored implementation rather than exposing structure.
- Dropping fixed facts or success criteria during reformulation.
- Selecting a promising restatement without mapping its result back.
